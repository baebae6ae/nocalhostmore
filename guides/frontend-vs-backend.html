프론트엔드만으로 충분할 때 vs 백엔드가 필요할 때

약 5분 · "무슨 언어로 만들지" 막막한 사람을 위한 글

초보에게 "파이썬 쓸래, 자바스크립트 쓸래?"는 잔인한 질문입니다. 뭐가 다른지 모르니까요. 사실 이건 언어의 문제가 아니라 "서버가 필요한가?"의 문제입니다. 이 질문의 답이 스택을 자동으로 정해줍니다.

프론트엔드가 뭐고, 백엔드가 뭔가

  • 프론트엔드 = 사용자의 브라우저 안에서 도는 부분(화면·버튼·클릭 반응). HTML·CSS·JavaScript.
  • 백엔드 = 눈에 안 보이는 서버에서 도는 부분(데이터 저장, 로그인 확인, 비밀 키로 외부 API 호출).

백엔드가 "필요 없는" 경우 → 프론트엔드만, 무료

다음이 모두 아니라면, 서버 없이 브라우저에서 다 끝낼 수 있습니다.

  • 비밀 키가 필요 없다 (외부 유료 API를 직접 안 쓴다)
  • 로그인/회원별 데이터가 없다
  • 서버에 저장할 게 없다 (있어도 그 브라우저의 localStorage면 충분)

예: 단위 변환기, 타이머, 색상 팔레트 생성기, 간단한 계산기. 이런 건 정적 호스팅(Vercel·Netlify·GitHub Pages)에 무료로 올릴 수 있고, 서버 비용이 0원입니다.

백엔드가 "필요한" 경우 → 파이썬(Streamlit) 추천

하나라도 해당하면 서버가 필요합니다.

  • 비밀 키를 쓴다 → 키는 프론트에 두면 노출되므로 반드시 서버에서 다뤄야 한다
  • 로그인이나 회원별 데이터가 있다
  • 데이터베이스에 영구 저장한다
  • 파일을 서버에서 처리하거나 AI·데이터 분석을 한다

이럴 땐 초보에게 Python + Streamlit이 특히 좋습니다. 화면과 서버를 한 번에 만들 수 있고, AI·데이터 라이브러리가 풍부하며, 예제가 많아 막힐 때 검색이 잘 됩니다.

가장 흔한 실수: 비밀 키가 필요한데 "프론트엔드만" 만드는 것. 프론트엔드는 소스가 공개돼 키가 그대로 털립니다. 비밀 키가 있으면 무조건 백엔드가 필요합니다.

그래서, 언어를 직접 고를 필요가 없다

"배포하나? 저장하나? 비밀 키 쓰나? 로그인 있나?" — 이 쉬운 질문들의 답이 서버 필요 여부를 결정하고, 그게 곧 스택을 결정합니다. 그래서 Nocalhostmore는 언어를 묻지 않고, 의도만 듣고 알아서 정합니다.

내 아이디어는 어느 쪽일까?

의도만 답하면 프론트엔드/백엔드와 배포 방법을 자동으로 정해드려요.
