로그인 기능, 정말 지금 필요한가요?

약 5분 · "일단 회원가입부터 만들어야지"라고 생각하는 사람을 위한 글

많은 바이브 코더가 프로젝트를 시작하자마자 "회원가입·로그인"부터 만듭니다. 왠지 "제대로 된 서비스"라면 당연히 있어야 할 것 같으니까요. 그런데 이건 종종 가장 먼저 만들 필요가 없는 기능입니다. 이 글은 다른 가이드들과 달리, "무조건 만들어라"가 아니라 "진짜 필요한지 먼저 따져보자"는 이야기입니다.

로그인은 생각보다 무겁다

로그인 하나를 "제대로" 만들려면 아래가 전부 딸려 옵니다.

  • 비밀번호 해싱·저장, 비밀번호 재설정 흐름
  • 이메일 인증 또는 소셜 로그인 연동
  • 세션/토큰 관리, 로그아웃, 자동 로그인
  • "내 정보 수정", "회원 탈퇴" 같은 부가 화면
  • 남의 계정에 접근 못 하게 막는 권한 검사 (가장 실수 많이 나는 지점)

이걸 다 만드는 동안, 정작 서비스의 핵심 기능은 뒷전으로 밀립니다. 그리고 권한 검사를 어설프게 하면, "로그인은 되는데 남의 데이터가 보이는" 훨씬 심각한 보안 사고로 이어집니다.

정말 필요한 경우

아래에 해당하면 로그인이 꼭 필요합니다. 미루지 마세요.

  • 사용자마다 "내 기록"이 있고, 그걸 다음에 다시 봐야 한다
  • 결제나 개인정보처럼 본인 확인이 반드시 필요하다
  • 사용자 간 권한 차이(관리자/일반 회원)가 있다

아직 필요 없을 수도 있는 경우

  • 지금은 "일단 만들어서 반응을 보고 싶다" 단계다 (MVP)
  • 브라우저에 저장해도 충분하다 — 예: 개인용 도구는 localStorage로 대체 가능
  • "나중에 계정 시스템이 필요할 수도 있으니까"라는 막연한 이유뿐이다

이런 경우엔 로그인 없이 먼저 출시하고, 정말 "내 계정이 있어야 하는 이유"가 생겼을 때 추가하는 게 낫습니다. 기능을 나중에 더하는 건 어렵지 않지만, 처음부터 과하게 만들어두고 안 쓰는 건 시간 낭비입니다.

나중에 쉽게 추가하려면

지금 로그인을 안 만들더라도, 나중을 위해 이 정도는 미리 해두면 좋습니다.

  • 데이터 모델에 user_id 컬럼 자리를 비워서라도 설계해두기
  • 비즈니스 로직과 화면을 분리해두기 (로그인 붙일 때 화면만 안 갈아엎어도 되게)
로그인은 "당연히 있어야 하는 것"이 아니라 "내 데이터가 필요한 순간" 붙이는 기능입니다.

내 서비스엔 로그인이 필요할까?

체크리스트에서 "각자 로그인해서 내 데이터를 본다"를 고를 때만 자동으로 로그인 규칙이 들어갑니다.
