데이터 저장이 필요할까? 서버·DB가 돈이 되는 순간

약 5분 · 영속성과 비용을 처음 고민하는 사람을 위한 글

"회원가입을 붙이고 싶어요", "사용자가 쓴 글이 남아야 해요". 이 순간부터 프로젝트는 조용히 돈이 드는 영역으로 들어섭니다. 무작정 DB부터 붙이면 관리가 복잡해지고, 반대로 필요한데 안 붙이면 데이터가 계속 사라집니다. 판단 기준을 잡아봅시다.

딱 하나만 물어보세요

"이 데이터, 새로고침하거나 서버가 꺼졌다 켜져도 남아 있어야 하나?"
  • 아니오 — 계산기, 변환기, 한 번 보여주고 끝나는 도구. 인메모리로 충분합니다. DB가 필요 없어요.
  • 예 — 회원정보, 작성 기록, 주문 내역. 데이터베이스(영속성)가 필요합니다.

많은 초보가 파이썬 리스트에 데이터를 쌓아두고 "왜 재접속하면 사라지죠?"라고 묻습니다. 서버 메모리는 재시작되면 비워집니다. 남아야 하는 데이터는 반드시 디스크에 기록되는 저장소(DB)에 넣어야 합니다.

무료로 시작하는 현실적인 순서

DB가 필요하다고 바로 비싼 서버를 살 필요는 없습니다. 단계적으로 올리세요.

  1. 개발·소규모: SQLite. 파일 하나짜리 DB로, 설치도 서버도 필요 없습니다. 완전 무료.
  2. 배포·성장: PostgreSQL. 여러 명이 동시에 쓰면 SQLite로는 한계가 옵니다. 이때 Supabase·Neon·Railway 같은 곳의 무료 티어로 시작하고, 트래픽이 늘면 유료로 올립니다.

핵심은 DB 접속 정보를 환경변수로 분리해두는 것입니다. 그러면 코드를 거의 안 고치고 SQLite → PostgreSQL로 갈아탈 수 있습니다. 그리고 SQL 문자열을 직접 이어붙이지 말고 SQLAlchemy 같은 ORM을 쓰세요 — 인젝션 사고를 막아줍니다.

"유료로 서버를 사야 할 수도 있다"는 신호

아래에 해당하면, 언젠가 매달 비용이 드는 구간에 들어간다고 미리 알고 시작하세요.

  • 각자 로그인해서 자기 데이터를 저장/조회한다 (회원제 서비스)
  • 모두가 함께 보는 게시판·대시보드에 데이터가 계속 쌓인다
  • 업로드한 파일을 영구 보관한다 (저장공간 비용)

반대로 "로그인 없는 도구"이고 저장이 필요 없다면, 서버 없이 무료 정적 호스팅만으로 배포할 수 있습니다. 돈을 아끼는 가장 확실한 방법은 필요 없는 DB를 붙이지 않는 것입니다.

내 아이디어엔 DB가 필요할까?

질문 몇 개에 답하면 DB 필요 여부와 예상 비용까지 알려드려요.
