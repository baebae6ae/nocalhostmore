로컬에선 되던 앱이 배포하면 터지는 5가지 이유

약 6분 · 초보 바이브 코더를 위한 글

"내 컴퓨터에선 완벽하게 돌아갔는데, 인터넷에 올리니까 이상해요." 바이브 코딩을 하다 보면 누구나 겪는 벽입니다. 문제는 대개 코드 실력이 아니라 처음 설계에 있습니다. AI가 "일단 돌아가는 코드"를 짜줬을 뿐, 여러 사람이 동시에 쓰는 실제 환경을 가정하지 않았기 때문이죠. 가장 흔한 5가지를 살펴봅니다.

1. 전역 변수에 사용자 데이터를 담았다

로컬에서 나 혼자 쓸 땐 전역 변수(global)에 값을 저장해도 문제가 없습니다. 그런데 배포해서 여러 명이 접속하면, 그 전역 변수는 모든 접속자가 공유합니다. A가 입력한 값이 B 화면에 튀어나오는 대참사가 벌어지죠.

해결: 사용자별 상태는 세션에 격리하세요. Streamlit이라면 st.session_state, 일반 서버라면 요청 스코프(세션/토큰)에 묶습니다. 자세한 원리는 상태 격리 가이드에서 다룹니다.

2. 업로드한 파일이 서버에서 사라진다

많은 무료 호스팅(예: Streamlit Cloud, Render 무료 티어)은 임시 파일 시스템을 씁니다. 재배포하거나 일정 시간이 지나면 서버가 초기화되면서 로컬 디스크에 저장한 파일이 전부 날아갑니다. "어제 올린 이미지가 사라졌어요"의 정체죠.

  • 일회성이면: 애초에 저장하지 말고 처리 후 finally에서 즉시 삭제하세요.
  • 계속 보관해야 하면: 로컬이 아니라 S3 같은 오브젝트 스토리지에 저장하고, 사용자 ID로 폴더를 나눕니다.

3. API 키를 코드에 그대로 박아놨다

OpenAI 키 같은 비밀 값을 코드에 직접 적고 GitHub에 올리면, 공개 저장소를 스캔하는 봇들이 수 분 내에 키를 훔쳐갑니다. 그 순간부터 남이 당신 계정으로 API를 호출하고, 요금은 당신에게 청구됩니다.

해결: 키는 환경변수로 분리하고(.env + python-dotenv, 또는 st.secrets), .env는 반드시 .gitignore에 넣으세요. 실전 세팅은 API 키 보안 가이드를 참고하세요.

4. 저장이 필요한데 데이터베이스가 없다

회원 정보나 기록을 파이썬 리스트/딕셔너리에 담아두면, 서버가 재시작되는 순간 모두 사라집니다. "새로고침하면 다 없어져요"는 버그가 아니라 영속성(persistence) 설계가 없다는 신호입니다.

내일 다시 접속해도 데이터가 남아야 한다면 데이터베이스가 필요합니다. 개발은 가벼운 SQLite로 시작하고, 운영은 PostgreSQL로 옮길 수 있게 접속 정보를 환경변수로 분리해두면 전환이 쉽습니다. 이때 SQLAlchemy 같은 ORM을 쓰면 SQL 문자열을 직접 조합하다 인젝션에 뚫리는 사고도 막을 수 있습니다.

5. 동시에 여러 명이 누를 걸 가정하지 않았다

"다 같이 보는 게시판"이나 "실시간 순위표"처럼 여러 사람이 같은 데이터를 동시에 바꾸는 경우, 단순히 변수에 값을 더하는 코드는 경쟁 상태(race condition)로 값이 꼬입니다. 공유 상태는 DB나 캐시(Redis)를 단일 진실 공급원으로 두고, 트랜잭션이나 락으로 동시 수정을 안전하게 처리해야 합니다.

정리 — 터지기 전에 물어봐야 할 질문들

결국 배포에서 무너지는 앱은 아래 질문을 코딩 전에 하지 않은 경우가 대부분입니다.

  • 이걸 나 혼자 쓰나, 여러 명이 쓰나?
  • 사용자마다 자기 데이터가 따로 있어야 하나?
  • 파일/기록을 저장해야 하나, 아니면 일회성인가?
  • 비밀 키가 들어가나? 어디에 배포하나?

이 질문들, 대신 물어봐 드릴게요
