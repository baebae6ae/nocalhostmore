파일 업로드, 이렇게 하면 서버가 터진다

약 6분 · 파일 업로드 기능을 붙이는 사람을 위한 글

"이미지 올리면 처리해주는 기능"은 인기 있지만, 바이브 코딩으로 대충 붙이면 세 가지가 터집니다. 파일이 서로 덮어써지고, 디스크가 가득 차고, 남의 파일에 접근됩니다. 하나씩 막아봅시다.

1. 원본 파일명을 그대로 쓰면 파일이 섞인다

두 사용자가 똑같이 photo.jpg를 올리면? 뒤에 올린 파일이 앞의 것을 덮어씁니다. 게다가 파일명에 ../../etc/passwd 같은 경로를 넣으면 엉뚱한 위치에 저장되는 경로 조작(path traversal) 공격도 가능합니다.

해결: 사용자가 보낸 파일명을 신뢰하지 마세요. 저장할 땐 uuid4()로 고유한 이름을 새로 만들고, 원래 확장자만 검증해서 붙입니다. 
import uuid, os
ext = os.path.splitext(uploaded.name)[1].lower()
if ext not in {".jpg", ".png", ".pdf"}:
    raise ValueError("허용되지 않는 형식")
safe_name = f"{uuid.uuid4().hex}{ext}"

2. 안 지우면 디스크가 가득 찬다

임시로 저장한 파일을 처리 후 지우지 않으면, 업로드가 쌓이면서 서버 저장공간이 꽉 찹니다. 특히 처리 중 에러가 나면 정리 코드를 건너뛰기 쉽죠. 그래서 try/finally의 finally에서 무조건 지워야 합니다. 

try:
    process(tmp_path)      # 여기서 에러가 나도
finally:
    if os.path.exists(tmp_path):
        os.remove(tmp_path)   # 파일은 반드시 정리된다

3. 용량 제한이 없으면 한 방에 터진다

누군가 5GB 파일을 올리면 서버 메모리가 폭발합니다. 서버 단에서 최대 크기를 정하고, 초과하면 거부하세요. 확장자·MIME 타입도 함께 확인해 "이미지인 척하는 실행 파일" 같은 걸 걸러냅니다.

영구 보관이라면: 로컬 말고 오브젝트 스토리지

"나중에도 볼 수 있게 저장"해야 한다면 서버 로컬 디스크는 답이 아닙니다(재배포 때 사라짐). AWS S3 같은 오브젝트 스토리지에 저장하고, 경로를 사용자 ID로 격리하세요. 예: uploads/{user_id}/{uuid}.jpg. 이렇게 하면 A가 B의 파일에 접근하는 사고를 구조적으로 막습니다.

UUID 파일명, 확장자·용량 검증, finally 강제 삭제. 영구 보관은 S3 + 사용자별 폴더로.

파일 처리 규칙, 자동으로 넣어드려요

"일회성 / 영구 보관"만 고르면 위 규칙이 프롬프트에 강제됩니다.
