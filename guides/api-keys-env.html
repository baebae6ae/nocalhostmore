API 키를 GitHub에 올려 요금 폭탄 맞지 않는 법

약 6분 · 비밀 값 관리를 처음 배우는 사람을 위한 글

AI 앱을 만들다 보면 OpenAI 키 같은 비밀 값이 필요합니다. 그런데 이걸 코드에 그대로 적어 GitHub에 올리는 순간, 공개 저장소를 24시간 스캔하는 봇들이 수 분 안에 키를 찾아냅니다. 그리고 남이 당신 계정으로 API를 마구 호출해, 다음 날 수십만 원 요금이 청구되는 "요금 폭탄" 사고로 이어집니다. 실제로 아주 흔한 일입니다.

왜 하드코딩이 위험한가

# ❌ 절대 하지 마세요
client = OpenAI(api_key="sk-abcd1234...")   # 코드에 키가 그대로

문제는 두 가지입니다. 첫째, GitHub에 올리면 전 세계에 공개됩니다. 둘째, 한 번 커밋하면 나중에 지워도 Git 히스토리에 영원히 남습니다. "커밋했다가 다음 커밋에서 삭제했으니 괜찮겠지"는 통하지 않습니다. 이미 유출된 키는 반드시 폐기하고 새로 발급해야 합니다.

해결의 핵심: 코드와 비밀을 분리한다

비밀 값은 코드에 두지 말고, 바깥(환경변수)에서 읽어오게 만듭니다. 배포하는 곳에 따라 방법이 갈립니다.

일반 클라우드 (Vercel · Render · AWS 등) → .env

프로젝트 폴더에 .env 파일을 만들고 키를 넣습니다.

# .env  (이 파일은 절대 커밋하지 않는다!)
OPENAI_API_KEY=sk-여기에_진짜_키

코드에서는 python-dotenv로 불러옵니다.

import os
from dotenv import load_dotenv

load_dotenv()
api_key = os.environ["OPENAI_API_KEY"]

Streamlit Community Cloud → st.secrets

Streamlit Cloud에 배포한다면 대시보드의 Secrets 칸에 값을 넣고, 코드에서는 이렇게 읽습니다. 

import streamlit as st
api_key = st.secrets["OPENAI_API_KEY"]

로컬 테스트용으로는 .streamlit/secrets.toml에 넣되, 이 파일 역시 커밋하면 안 됩니다.

가장 중요한 한 줄: .gitignore

비밀 파일이 실수로 올라가는 걸 막는 안전장치가 .gitignore입니다. 아래를 반드시 추가하세요. 

# .gitignore
.env
.streamlit/secrets.toml

그리고 팀원이나 미래의 나를 위해, 값이 비어 있는 예시 파일을 대신 올려두면 좋습니다. 

# .env.example  (이건 커밋해도 안전 — 값이 비어 있으니까)
OPENAI_API_KEY=

보너스: 요금 폭탄 2차 방어선

키를 잘 숨겨도, 코드 버그로 API를 무한 반복 호출하면 요금이 폭발할 수 있습니다. 습관을 들이세요.

  • API 호출은 타임아웃·재시도(backoff)로 감싸고, 실패해도 앱이 죽지 않게 합니다.
  • 한 번에 보내는 요청 크기와 횟수에 상한(가드)을 둡니다.
  • OpenAI 등 대시보드에서 사용량 한도(usage limit)를 설정해 둡니다.
요약: 키는 코드 밖으로(.env / st.secrets), .gitignore로 잠그고, 유출되면 즉시 폐기·재발급. 여기에 호출 상한까지.

이 세팅, 프롬프트에 자동으로 넣어드려요
